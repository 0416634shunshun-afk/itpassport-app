# 新卒研修 発表資料作成プロンプト集

新卒研修として Claude を活用してツールを開発し、その**開発プロセスをメイン**に発表するための
プロンプト集。開発の節目ごとに使う「記録用プロンプト」と、発表準備段階で使う「資料化プロンプト」に分かれている。

## 使い方

1. 開発中は「1. 開発ログを残すプロンプト」を節目ごとに実行し、`dev-log.md` に記録を蓄積する
2. ある程度ログが溜まったら「2. Claude活用の振り返りプロンプト」でAI活用の学びを言語化する
3. 発表が近づいたら「3. 発表構成を考えるプロンプト」で構成案を作る
4. 最後に「4. スライド生成プロンプト」で実際のスライドに落とし込む

---

## 1. 開発中に記録を残すプロンプト

開発の区切り(機能実装完了、詰まった問題を解決した時など)ごとに投げる。事後に思い出して書くより正確で楽。

```
ここまでの開発内容を振り返って、以下を箇条書きでまとめてください。
①やったこと(変更・実装した機能)
②なぜその設計・実装方針にしたか
③詰まった点とどう解決したか
④次にやること
`dev-log.md` に追記する形で出力してください。
```

### コミット/PR用の補助プロンプト

```
今回の変更について、何を・なぜ変更したかをコミットメッセージとPR説明文としてまとめてください。
後で発表資料に転用しやすいよう、背景と意図が伝わる書き方にしてください。
```

---

## 2. Claude活用の振り返りプロンプト

新卒研修の発表では、成果物そのものより「AIをどう使ったか」が評価されやすい。ある程度開発が進んだ段階で使う。

```
これまでのやり取りの中で、良い指示の出し方ができた例と、曖昧で手戻りが発生した例を
それぞれ2〜3個挙げてください。
Before(最初のプロンプト)→気づき→After(改善したプロンプト)の形式で整理してください。
```

```
開発の中でClaudeに任せた部分と、自分で判断・修正した部分を整理してください。
AIに任せてよかった作業、逆に人間が確認すべきだった作業を分けてください。
```

---

## 3. 発表構成を考えるプロンプト

`dev-log.md` がある程度溜まった段階で、構成案を作らせる。

```
以下は開発ログです。新卒研修の発表資料(開発プロセスをメインに、10分程度)の構成案を作ってください。

想定する流れ:
①テーマ・課題設定
②設計方針
③実装の流れ(時系列)
④つまずきと解決
⑤Claude活用の工夫
⑥今後の展望・学び

各スライドのタイトルと要点を3行程度でまとめてください。

[ここに dev-log.md の内容を貼り付け]
```

---

## 4. スライド生成プロンプト

構成案が固まったら、実際のパワーポイントを生成させる。

```
上記の構成案をもとに、パワーポイントのスライドを作成してください。
1スライドあたり情報を詰め込みすぎず、コードの前後比較やスクリーンショットを
入れる箇所は「[ここに画像]」のように示してください。
```

---

## 運用のコツ

- **開発初日から「1. 開発ログを残すプロンプト」を使う**ことを決めておくと、発表準備が格段に楽になる(後からログを再構成するのは大変)
- コミットメッセージやPR説明にも「なぜこの変更をしたか」を書かせる癖をつけておくと、そのまま発表資料に転用できる
- 発表直前にまとめて振り返るのではなく、開発と並行してログを育てていくのが基本方針
